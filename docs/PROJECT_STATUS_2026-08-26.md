# Iris Agent 项目状态（2026-08-26）

> 更新时间：2026-08-26  
> 项目定位：面向日常对话、资料检索、知识整理、报告生成与聊天平台接入的个人智能 Agent，不以代码开发为主要用途。

## 1. 已完成内容

### 1.1 对话与 Agent 运行时

- 已实现流式对话、停止生成、重新生成、工具调用展示、会话保存与历史搜索。
- 支持“快速 / 思考”响应策略、知识库选择、附件读取和引用展示。
- 支持运行时模型 Profile 切换；`agent.yaml` 作为默认配置，设置页中的活动 Profile 可覆盖默认模型连接。
- 已加入上下文压缩、长期记忆、用户画像和任务运行时快照。

### 1.2 工具、Skills 与 MCP

- 已接入时间、文件读取/写入、命令执行、网页搜索、网页抓取、记忆、知识库、Skills 和 MCP 工具。
- MCP 中心支持服务配置、启用、工具发现、工具授权、超时、环境变量和调用事件展示。
- Skills 中心支持内置 Skill、用户 Skill、启用与调用。

### 1.3 知识库与文档思维导图

- 已实现本地知识库集合、文档导入、分块、关键词/向量/图谱混合召回、重排、引用和数据导入导出。
- 已实现知识图谱实体与关系抽取、可视化、节点拖动、实体编辑、合并与删除。
- 已新增“文档级思维导图”：以整份文档为根节点，生成主题和关键观点两级结构，不再直接把每个分块或句子当作图节点。
- 思维导图支持查看对应原文证据；本地模型不可用时提供受控的降级结构。
- 当前思维导图限制为最多 8 个主题、每个主题最多 6 个观点、总计最多 40 个节点，并对长文档均匀抽样。

### 1.4 内部多 Agent 委派

- 已实现单任务委派、批量并行委派和有依赖关系的工作流委派。
- 已实现后台委派持久化、委派列表、详情查询和取消接口，前端任务中心可以展示与取消委派。
- 已内置四种一层子 Agent 角色模板：
  - `general`：通用任务。
  - `researcher`：资料检索和来源整理。
  - `knowledge_organizer`：知识归纳、去重和结构化。
  - `report_writer`：根据现有资料生成报告成稿。
- 角色模板会提供专属提示词、默认工具和默认轮次；调用者显式传入的工具与轮次优先。

### 1.5 QQ 与消息渠道

- 已接入 QQ OneBot 11 反向 WebSocket，支持接收私聊、可选群聊、白名单控制、文字回复和私聊文件发送。
- 侧边栏已增加“消息渠道”模块，使用独立的渠道连接图标。
- 消息渠道页面支持：
  - 查看 QQ 是否启用、是否连接。
  - 显示并复制反向 WebSocket 地址。
  - 刷新连接状态。
  - 向指定 QQ 号发送测试消息。
  - 展示 NapCat/Lagrange 接入步骤。
- 当前 QQ 连接地址为 `ws://localhost:8000/gateway/qq/ws`。

### 1.6 前端与其他业务模块

- 已完成组合式侧边栏与折叠状态修复，折叠后保留菜单图标、首页入口和折叠按钮。
- 已接入聊天、AI 日报、每日资讯、流程图、Skills、自动化、任务中心、记忆、知识库、审查、MCP 和消息渠道页面。
- 已具备自动化任务、热点雷达、日报生成、UML 流程图、通知、附件清理和任务队列能力。

### 1.7 最近验证结果

- 子 Agent 角色模板及委派链路：`36 passed`。
- QQ 消息渠道 API 与既有网关测试：`40 passed`。
- 消息渠道页面与侧边栏测试：`20 passed`。
- React/TypeScript 生产构建成功。

## 4. 未解决问题

- 当前工作树仍有大量未提交修改，尚未形成清晰、可回滚的稳定版本点。
- Iris 已支持内部多 Agent 委派，但尚未实现标准 A2A 协议；没有 Agent Card、A2A 服务端接口和远程 Agent 客户端。
- 后台子 Agent 完成后的结果主要通过委派记录查看，尚未自动回填并唤醒原始聊天会话。
- 消息渠道页面只能管理 Iris 侧的连接状态；NapCat/Lagrange 仍需独立启动和登录，页面不能直接启动 QQ 客户端进程。
- QQ 连接状态只反映当前内存中的 WebSocket，尚未展示最近连接时间、断线原因和自动重连记录。
- `gateway.enabled` 顶层开关目前没有完整控制所有适配器创建逻辑，实际是否创建 QQ 适配器主要由 `gateway.qq.enabled` 决定。
- 文档思维导图已改为整份文档结构总结，但最终质量仍依赖本地抽取模型和文档结构，需要用真实长文档继续观察主题合并效果。
- 当前前端生产包约 `1.58MB`，Vite 存在大包提醒，首屏仍有进一步优化空间。
- 企业微信配置和真实环境回调尚未启用验证。

## 5. 下一步建议

1. **先完成 QQ 真实链路验收**：使用实际 NapCat/Lagrange 连接，验证私聊问答、断线状态、测试发送和文件发送。
2. **完善后台委派结果回传**：子 Agent 完成后自动通知原会话并插入结果，这是当前多 Agent 最有价值的下一步，不需要引入 Hermes 的多层编排。
3. **继续观察文档思维导图质量**：选取几份长文档验证主题数量、去重、层级和原文证据；发现问题直接调整抽取提示与节点上限。
4. **整理可回滚版本点**：区分现有用户修改与本轮新增功能，完成一次稳定提交，避免继续在大量未提交改动上叠加功能。
5. **补充基础运行观测**：记录模型首字时间、知识检索耗时、子 Agent 执行时间和 QQ 最近连接状态。
6. **暂不优先实现标准 A2A**：只有需要连接外部独立 Agent 时再增加 A2A Server；目前一层内部角色委派已经足够覆盖资料检索、知识整理和报告生成。
