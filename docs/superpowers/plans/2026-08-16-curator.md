# Curator 后台审查一期执行计划

日期：2026-08-16
分支：feature/curator（新建 worktree）

## 目标

按 `2026-08-16-curator-design.md` 落地 curator 一期：记忆 + 画像的去重/冲突审查，产出报告 → 用户确认后应用。

## 任务拆解

### 1. 数据模型与仓储

- `iris_agent/curator/models.py`：`CuratorReport` / `CuratorSuggestion`（白名单字段，targets 只存 id）。
- `iris_agent/curator/repository.py`：每条报告一文件 `data/curator/reports/<id>.json`，原子写 + Windows 文件锁，`max_reports` 裁剪。
- `iris_agent/config/settings.py`：新增 `CuratorSettings`（directory/merge_threshold/conflict_threshold/enable_llm/max_pairs_per_run/max_reports）。
- 测试：模型校验、仓储 save/get/list/update、裁剪上限。

### 2. 相似度引擎（确定性去重）

- `iris_agent/curator/similarity.py`：复用 `OllamaEmbedder` 做余弦相似度；embedder 抛错时降级为 `session_search.tokenizer.tokenize` 的 bigram 重叠度。
- 候选对生成：记忆同 category 两两、画像同字段两两，`max_pairs_per_run` 截断。
- 分桶：`> merge_threshold` 判重复；`≤ conflict_threshold` 丢弃；区间内交 LLM 精判。
- 测试：分桶正确、降级不崩溃、空数据。

### 3. LLM 冲突精判

- `iris_agent/curator/referee.py`：把区间候选对交给 provider 精判 `duplicate/conflict/unrelated`（只发条目文本）。
- `enable_llm=false` 跳过；LLM 异常时跳过精判（best-effort，不影响确定性去重结果）。
- 测试：三种输出映射、开关、异常降级。

### 4. 服务与装配

- `iris_agent/curator/service.py`：`CuratorService.run/apply/dismiss`。
  - `run` 只读，产出并落盘报告。
  - `apply` 复用 `MemoryService.delete` / `ProfileService.replace`，目标 id 缺失跳过。
- `bootstrap.py`：构造 `CuratorService` 挂到 `ApplicationServices`（依赖 Memory/Profile/embedder/provider）。
- 测试：run 只读、apply 正确删改、dismiss 状态、装配。

### 5. API 与前端

- `iris_agent/api/curator_api.py`：`POST /api/curator/run`、`GET /api/curator/reports[/{id}]`、`POST .../apply`、`POST .../dismiss`；接入 `app.py`。
- 前端：`web-react` 新增 `curator` 视图 + `CuratorPage` + API 客户端 + 侧栏入口（立即审查/报告列表/建议卡片/应用忽略）。
- 测试：API 白名单与校验；前端渲染与交互。

## 验证

- 后端全量 pytest（`-p no:cacheprovider --basetemp=<全新目录>`）应通过，含 curator 新增用例。
- 前端 `npm test` + `npm run build`。
- 端到端冒烟：造几条重复/冲突记忆 → run 出报告 → 前端应用 → 记忆被正确去重。

## 依赖与风险

- 复用已启用的 `bge-m3`（本地 Ollama）与 LLM provider，零新 pip 依赖。
- 风险：`OllamaEmbedder` 位于 `knowledge/embedder.py`，curator 直接 import 复用；如后续多模块共用再考虑提升到共享目录（一期不重构）。
