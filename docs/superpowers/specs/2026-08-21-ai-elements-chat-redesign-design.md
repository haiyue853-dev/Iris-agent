# Iris AI Elements 风格聊天页面重设计

## 目标

在不替换现有 `assistant-ui` 运行时和 Python API 的前提下，将 Iris 的完整应用框架与聊天界面重设计为接近 AI Elements Chatbot 示例的视觉和交互。保留现有业务入口、会话、流式回复、附件、工具审批和停止生成能力。

参考：https://elements.ai-sdk.dev/examples/chatbot

## 页面框架

- 使用清爽的浅色中性主题、细边框、柔和圆角和更克制的阴影。
- 左侧为可折叠导航栏，保留 Iris 品牌、新建会话、全部现有功能入口、历史会话和设置。
- 导航栏缩窄并降低视觉重量；当前入口和当前会话使用低对比度背景突出。
- 右侧主内容区占据剩余空间。非聊天业务页面继续使用原组件，仅共享新的页面框架和主题变量。

## 聊天区域

- 消息列居中，采用统一最大宽度。
- 用户消息显示为紧凑的浅色圆角气泡。
- 助手消息以无边框正文为主，保留 Markdown、代码块、消息操作和分支切换。
- 欢迎页使用简短标题、说明文字和居中的主输入框。
- 历史会话、空会话和流式会话继续复用现有数据流。

## 输入区

- 输入区固定在聊天区域底部，使用 AI Elements 风格的大圆角组合框。
- 附件与扩展操作位于左下方，发送或停止操作位于右下方。
- 保留现有中文输入法兼容修复、附件上传、Enter 发送和 Shift+Enter 换行。
- 输入区背景与页面背景之间使用轻微遮罩或边界，不遮挡消息内容。

## 推理与来源

- 推理显示为默认折叠的紧凑行，标题为“思考过程”或带持续时间的状态。
- 来源显示为“使用 N 个来源”的折叠项；展开后显示来源列表。
- 两类内容均嵌入对应助手消息，不创建独立的大卡片。

## 工具调用聚合

- 同一条助手消息中的普通工具调用聚合成一个紧凑小窗。
- 聚合标题根据状态显示“正在执行 N 个工具”“已执行 N 个工具”或“有工具执行失败”。
- 聚合窗默认折叠；展开后显示工具名称、状态图标和简短状态。
- 每个工具项可单独展开，查看参数、结果、取消原因或错误。
- 正在等待用户决定的审批卡片保持独立展示，不被折叠进聚合窗。
- 终端类工具纳入聚合列表；展开单项时继续复用现有终端结果视图。
- 单个普通工具也使用聚合窗，以保持消息布局一致。

## 组件边界

- `App` 继续负责视图路由和应用框架。
- `Sidebar` 保留数据与事件接口，只重构结构和样式。
- `AssistantChat` 和 `irisRuntime` 不改变后端协议。
- `Thread` 负责新的消息布局和输入区。
- 新增消息级工具聚合组件，接收一组工具消息部件并负责聚合、展开和状态摘要。
- 现有审批卡、终端视图和默认工具详情作为聚合项的详情渲染器复用。

## 数据与状态

- 不改变会话、消息和 AgentEvent 类型。
- 工具聚合仅发生在显示层，按当前助手消息中的工具部件分组。
- 聚合窗和单项展开状态为本地 UI 状态，不写入后端。
- 流式过程中新增工具时，计数和状态实时更新，用户已展开的聚合窗不自动关闭。

## 错误与可访问性

- 工具失败和取消必须在折叠标题与单项列表中可见。
- 所有折叠按钮使用原生按钮，并提供 `aria-expanded` 和可读标签。
- 键盘可操作导航、发送、停止、折叠和工具详情。
- 后端错误继续显示在对应助手消息内，不阻塞下一次输入。

## 测试与验收

- 组件测试覆盖侧栏折叠、欢迎页、输入发送、中文组合输入和消息布局。
- 工具聚合测试覆盖零项、单项、多项、运行中、成功、失败、取消及审批排除。
- 验证流式新增工具时聚合计数更新，展开状态保持。
- 运行完整前端测试、TypeScript/Vite 构建和 lint。
- 在浏览器中验证桌面与窄屏布局、历史会话切换、附件、工具审批和停止生成。

## 不在范围内

- 不迁移到 AI SDK 或 AI Elements 的聊天运行时。
- 不修改 Python API、NDJSON 事件协议、数据持久化和业务页面内部功能。
- 不新增模型选择、语音输入或网页搜索开关；示例中这些功能只作为视觉参考。
