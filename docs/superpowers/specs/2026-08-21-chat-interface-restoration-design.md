# Iris 聊天界面恢复设计

## 背景与目标

当前聊天页使用 `@assistant-ui/react` 组件和 Tailwind CSS v4 工具类，但 `App.css` 中未分层的全局 `*` 重置覆盖了 Tailwind 分层工具类的 margin、padding 等声明，造成欢迎区、建议卡片和输入区贴左、拥挤及错位。

本次恢复以 AI Elements / assistant-ui 的聊天体验为视觉与交互参考，同时保留 Iris 已有侧边栏、会话管理、流式事件、工具审批及后端协议。范围聚焦聊天核心组件，不引入模型选择器、任务队列或计划工作台。

## 方案选择

采用“修复 CSS 层级并渐进补齐现有 assistant-ui 线程”的方案。

不整页复制 AI Elements 示例，因为这会替换现有运行时适配层并增加会话、审批和流式事件回归风险；不重新自研聊天框架，因为现有 assistant-ui 已提供消息、编辑、分支、附件和 composer primitives。

## 布局与视觉

- 保留 Iris 左侧栏和中性灰主题。
- 聊天线程占满主内容区，内部正文和输入区使用约 `44rem` 的居中单栏。
- 空会话欢迎区在可用高度内垂直居中；建议卡片桌面端两列、窄屏单列。
- 输入框位于线程底部，随滚动保持可用；附件显示在输入框内部上方。
- 用户消息保持右侧气泡，助手消息使用左对齐无重边框正文布局。
- 桌面与窄屏均不得出现页面级横向溢出。

## 核心聊天组件

### 输入与附件

- 支持文件选择和拖放。
- 待发送附件可预览文件名、类型或缩略图，并可移除。
- 已发送附件展示在用户消息中。
- 上传、解析或发送失败时提供可理解的错误状态，不清空仍可重试的输入内容。

### 消息正文与操作

- 助手正文支持 Markdown、代码块和链接。
- 助手消息提供复制与重试；用户消息保留编辑能力。
- 生成期间显示停止按钮；线程离开底部时显示滚动到底部按钮。
- 消息错误紧邻对应消息展示。

### 思考与工具状态

- 当后端事件包含推理或过程内容时，显示可折叠思考区。
- 流式思考期间使用克制的动态指示；结束后保留可展开摘要或内容。
- 工具调用按运行中、等待审批、成功和失败四类状态展示。
- 继续复用 Iris 现有工具审批数据流，不复制新的审批状态源。

### 来源引用

- 当消息事件包含来源信息时，在助手消息正文附近展示紧凑来源列表。
- 来源链接显示可识别标题；缺失标题时使用安全的域名或回退标签。
- 外部链接使用安全打开方式。

## 数据流与组件边界

- `AssistantChat` 继续负责构造 Iris runtime adapter 与上下文。
- `Thread` 负责线程布局、欢迎区、composer 和消息 primitive 组合。
- 附件组件只处理附件呈现和 composer 操作，上传与事件转换继续由现有 runtime/API 层负责。
- 推理、工具和来源展示从规范化消息 parts 读取；若现有 adapter 尚未产出对应 part，仅在 adapter 边界补充映射，不在展示组件中解析原始后端事件。
- 工具审批继续通过 `IrisChatContext.resolveApproval` 回传。

## CSS 修复策略

- 将全局 reset 放入明确的基础层，避免未分层规则压过 Tailwind utilities。
- 保留 `box-sizing: border-box` 和页面级高度约束。
- 不用大量 `!important` 或逐组件补丁掩盖级联问题。
- 仅在 Iris 壳层确有需要时保留传统全局类；聊天组件优先使用现有 Tailwind/assistant-ui 类。

## 错误处理

- 附件、消息发送、流式生成和工具调用错误分别在最接近操作的位置展示。
- 无法识别的消息 part 由现有 fallback 工具视图安全呈现，不应导致整条消息或线程崩溃。
- 缺失推理或来源数据时不渲染空容器。

## 测试与验收

- 先添加能够复现“Tailwind 间距被全局 reset 覆盖”的布局回归检查，再修改 CSS。
- 覆盖空线程欢迎区、建议卡片、composer、附件、思考状态、工具状态和来源渲染。
- 运行现有前端测试、lint 和生产构建。
- 使用本地浏览器在桌面与窄屏验证：内容居中、输入框完整、无横向溢出、附件与消息操作可见。

## 非目标

- 不在本次加入模型选择器、任务队列、计划面板或新的后端协议。
- 不重做 Iris 侧边栏和其他工作台页面。
- 不复制参考站点品牌、导航或完整页面外壳。
