# Iris Agent v0.2 工具审批与可视化设计

## 目标与范围

Iris Agent v0.2 为受控写文件和命令执行建立统一审批层，并让 Web 与 CLI 共用同一套权限、决策和审计机制。

首批新增 `write_file`、`apply_patch` 和 `run_command`。现有 `read_file`、`list_directory` 默认免审但继续受工作区限制。本阶段不提供删除、递归移动、管理员命令或工作区外操作。

## 架构

```text
iris_agent/
├── approvals/
│   ├── models.py       # ApprovalRequest、Decision、Rule
│   ├── policy.py       # 评估允许、审批或禁止
│   ├── store.py        # 持久化永久规则
│   └── broker.py       # 创建请求、等待决策、超时与取消
├── tools/
│   ├── builtin/
│   │   ├── write_file.py
│   │   ├── patch_file.py
│   │   └── command.py
│   └── registry.py
└── core/
    └── agent.py
```

工具执行链为：参数校验、策略评估、必要时创建审批、等待 Web 或 CLI 决策、再次校验、执行工具、写入审计、返回结构化结果。审批核心不依赖 FastAPI 或 CLI。

## 授权级别

- `allow_once`：只允许当前调用。
- `allow_session`：当前会话内相同策略范围免审。
- `allow_always`：持久化规则并对后续会话生效。
- `deny`：拒绝本次调用，将结果交给模型。

文件授权绑定工具名称和工作区相对路径范围。命令授权绑定规范化的可执行文件与参数前缀，例如 `git status`，不得放行整个 Shell。

会话授权保存在进程内并以 `session_id` 隔离；永久规则以原子 JSON 文件持久化。规则文件损坏时忽略损坏内容并重新审批。

## 审批请求生命周期

审批请求包含不可变的 ID、会话 ID、工具、参数副本、摘要、风险等级、创建时间和失效时间。默认等待 120 秒。

用户停止生成、客户端取消或超时会使请求失效。重复决策返回冲突错误。服务重启后未决请求全部视为拒绝。批准后执行前必须重新验证路径和参数，避免等待期间环境变化造成越权。

非交互式 CLI 默认拒绝，不能自动批准。

## 流式事件与 API

新增事件：

```json
{
  "type": "approval_required",
  "data": {
    "approval_id": "approval_xxx",
    "tool": "run_command",
    "summary": "运行命令：pytest -q",
    "arguments": {"executable": "pytest", "args": ["-q"]},
    "risk": "medium",
    "expires_at": 1780000000
  }
}
```

决策接口为 `POST /api/approvals/{approval_id}/decision`。请求体包含 `decision`。Agent 的 NDJSON 响应在审批期间保持等待，决策后继续输出工具和文本事件。

审批卡片支持待处理、执行中、成功、失败、拒绝和超时状态。审批参数创建后不可由客户端修改。

## Web 与 CLI 交互

Web 在触发工具调用的助手消息下展示审批卡片，包含工具、风险、命令或文件、可展开参数、倒计时及四个决策按钮。提交后按钮禁用，防止重复决策。审批期间“停止”操作会取消请求。

CLI 显示相同信息并读取一次明确选择；检测不到交互终端时直接拒绝。

## 文件工具安全

`write_file` 完整创建或覆盖文件，`apply_patch` 执行局部文本补丁。二者均满足：

- 只访问配置的 `workspace_root`。
- 解析 `..` 和符号链接后仍必须位于工作区。
- 审批摘要包含目标路径、存在状态和预计修改大小。
- 使用同目录临时文件和原子替换。
- 单次输入上限 1 MB。
- 拒绝 `.env`、密钥文件及配置的保护路径。

## 命令工具安全

`run_command` 使用 `executable` 与 `args` 数组，不以拼接字符串作为默认执行接口。工作目录必须位于工作区。

- 默认超时 60 秒，最大 600 秒。
- 分别截断标准输出和标准错误。
- 取消或超时后终止完整子进程树。
- 禁止管理员提权和交互式程序。
- Shell 管道、重定向、命令替换和复合命令不继承普通前缀规则，始终重新审批。
- 执行环境使用明确允许的环境变量集合，不把应用密钥传给子进程。

## 审计

每次受控调用记录时间、会话、审批 ID、工具、脱敏参数摘要、决策及来源、执行结果、退出码和耗时。日志不记录 API Key、Token、密码或环境变量值。

审计写入失败时关闭执行；受控工具不得在缺少审计记录的情况下运行。

## 错误处理

- 参数无效：不创建审批，返回 `invalid_tool_arguments`。
- 拒绝：返回 `approval_denied` 工具结果。
- 超时：返回 `approval_timeout`。
- 取消：返回 `approval_cancelled`。
- 重复决策：API 返回 `approval_already_resolved`。
- 执行失败：写入审计并返回结构化工具错误。
- 永久规则损坏：记录警告并默认重新审批。

拒绝、超时和工具失败作为工具结果继续交给模型；审批基础设施或审计失败则终止本次受控执行。

## 测试策略

- 策略：四种决策、会话隔离、永久规则、命令前缀和路径范围。
- Broker：并发审批、超时、取消、重复决策和不可变参数。
- 文件：路径逃逸、符号链接、保护路径、大小限制和原子写入。
- 命令：参数数组、工作目录、环境过滤、超时、取消、进程树和输出截断。
- API：审批事件、决策接口、稳定错误码和断线取消。
- CLI：交互决策及非交互默认拒绝。
- Web：事件归并、倒计时、状态切换和重复提交保护。

## 验收标准

- Web 和 CLI 均支持允许一次、本会话允许、始终允许与拒绝。
- 会话规则不泄漏，永久规则重启后有效。
- 未审批、拒绝、超时、停止或断线的操作绝不执行。
- 文件工具无法离开工作区或修改保护路径。
- 命令超时和取消后不遗留子进程。
- 审计日志不包含敏感信息。
- 现有聊天、会话与只读工具无回归。
- Python 测试、React lint、TypeScript 和 Vite 构建全部通过。

## 后续阶段

v0.2 完成后，MCP 工具将通过相同的 `ToolRegistry` 和审批策略接入；Skills、记忆和子 Agent 不进入本阶段。
