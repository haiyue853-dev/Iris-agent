# 快速联网与可见研究进度设计

日期：2026-08-23

## 目标

把普通联网问答的体感从“长时间只转圈”改成快速、有限、可解释的过程。默认快速模式只做一次精准搜索，只有证据不足时读取最多两个页面；用户明确要求深入研究时，才允许多查询和最多三个页面读取。

## 已确认根因

历史任务记录显示单次 `web_search` 通常为 0.3–1.8 秒，单次 `fetch_page` 通常为 0.3–4.3 秒。主要延迟来自一次回答连续执行多次搜索和页面读取、多个工具串行执行，以及工具卡没有展示当前阶段。

## 行为策略

- 普通联网：一次搜索；摘要足够则直接回答；需要核对原文时最多读取两个高质量页面。
- 深度研究：仅在用户明确使用“深入研究、全面调查、交叉验证”等意图时启用；通常 2–4 个互补查询，页面读取总数最多三个。
- 搜索默认超时 6 秒、每个源尝试一次；失败后立即回退，不把同一失败重复等待两遍。
- 同一模型响应中的多个 `fetch_page` 属于只读调用，可最多三个并行执行。其他工具维持原串行和审批语义。
- 取消任务时停止等待并行批次，不再把迟到结果发送给模型。

## 进度界面

沿用现有 `tool_started` / `tool_finished` 流事件，不增加新的协议：

- 搜索运行中显示“正在搜索：关键词”。
- 搜索完成显示“找到 N 个结果”。
- 多页面读取显示“正在读取网页 X/Y”。
- 失败和取消继续使用现有状态样式。

## 验收标准

- 默认配置为 6 秒超时、每源一次尝试。
- 研究 Skill 明确区分快速与深度模式及页面上限。
- 两个以上 `fetch_page` 调用并行，结果按模型原调用顺序回填。
- 审批工具、写工具和其他工具不并行。
- 工具卡显示搜索词、结果数和网页读取进度。
- 后端、前端测试和前端构建通过。
