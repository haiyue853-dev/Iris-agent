# 自定义模型服务与空白聊天布局设计

## 目标

恢复清晰的聊天页状态切换，并确保用户配置的 OpenAI 兼容模型服务能够被保存、验证并立即用于后续对话。

## 范围

- 空白对话页中，欢迎内容与消息输入框共同位于可用聊天区域的中部。
- 用户发送第一条消息后，输入框切换为聊天区域底部的固定输入栏。
- 删除空白页中的两个英文示例提问按钮及其占位空间。
- 设置页支持自定义 API Key、Base URL 和模型名称。
- 设置页提供连接测试，并针对常见失败给出明确反馈。

不在本次范围内：增加新的模型供应商协议、模型列表自动发现、保存多套服务配置，或更改现有对话协议。

## 页面状态与布局

聊天页根据当前线程是否存在消息呈现两种状态：

1. **空白状态**：欢迎语和输入框作为一个居中内容组显示。输入框位于欢迎语下方，整体在聊天主区域视觉中部附近；移动端使用可视高度和安全区约束，避免软键盘或窄屏造成遮挡。
2. **对话状态**：从第一条用户消息进入线程后，消息列表占据主体空间，输入框回到底部并保持现有的滚动和粘滞行为。切换只改变布局，不清空草稿、附件或输入焦点。

示例建议组件不再渲染，相关英文文案和空白占位一并移除。

## 自定义模型服务

设置表单保留三个字段：API Key、Base URL、模型名称。

- Base URL 必须是完整的 `http://` 或 `https://` 地址。保存时规范化末尾斜杠，但不擅自追加供应商专属路径。
- API Key 输入继续使用密码样式。已有密钥不回传明文；编辑时留空表示保留当前密钥，输入新值表示替换。
- 模型名称按用户输入保存，用于后续请求。
- 保存成功后，后端同步刷新当前进程中的客户端配置，使新对话无需重启即可使用；配置同时持久化，重启后仍然生效。

现有后端继续以 OpenAI 兼容接口为边界。自定义地址若使用不同协议，不承诺兼容。

## 连接测试数据流

设置页提供“测试连接”操作。前端把当前表单中的 Base URL、模型名称和可选的新 API Key发送给后端专用测试接口；如果 API Key 留空，后端使用已保存的密钥。测试操作不保存表单。

后端使用临时客户端发起轻量级的 OpenAI 兼容请求，不修改运行时配置。结果归一化为：

- 连接成功；
- 地址无效或服务不可达；
- API Key 鉴权失败；
- 模型不存在或无权访问；
- 其他服务端错误。

前端在表单内展示结果，并在请求期间禁用重复测试。密钥不得出现在日志、响应正文或错误提示中。

## 错误处理

- URL 格式错误在前端提交前提示，后端再次校验。
- 保存失败时保留用户输入，并显示后端返回的安全错误信息。
- 测试连接失败不阻止用户继续编辑，也不覆盖当前已生效配置。
- 缺少可用 API Key 时，测试接口返回明确提示，而不是发起匿名请求。

## 组件边界

- 聊天线程组件负责判断空白/对话状态并选择输入框布局。
- 输入框组件本身保持单一实现，由两个布局容器复用，避免功能或样式分叉。
- 设置表单负责输入状态、基础校验和反馈展示。
- 设置 API 客户端负责保存与测试连接请求。
- 后端设置接口负责持久化和实时刷新；连接测试接口只负责临时验证。

## 测试与验收

- 组件测试验证：空白线程输入框居中、存在消息时输入框位于底部、英文建议按钮不存在。
- 设置表单测试验证：URL 校验、留空密钥语义、测试中禁用状态及各类反馈。
- 后端测试验证：保存后实时配置更新、留空密钥不覆盖、测试连接不修改运行配置、错误结果正确归类且不泄露密钥。
- 构建、静态检查和现有测试套件必须通过。
- 在桌面宽度和移动端宽度下进行实际页面检查，确认无横向溢出，空白页居中且对话后输入栏稳定停靠底部。
