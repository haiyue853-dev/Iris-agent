# MCP 工具调用链设计

## 目标与范围

将已启用且在白名单内的 stdio MCP 工具接入主对话的 `ToolRegistry`，使模型能够调用工具并获得结果。支持读操作的直接执行，以及写操作在聊天界面获得用户确认后执行。

本次不扩展 MCP 服务管理页的环境变量编辑、日志、删除或超时配置；不保留常驻子进程；不改变内置工具接口。

## MCP 运行时适配

`McpCenterService` 新增运行时工具发现与调用能力。每次发现或调用均启动一个子进程，按 JSON-RPC 顺序执行：`initialize`、`notifications/initialized`、`tools/list`（仅发现时）或 `tools/call`（调用时），读取匹配的响应 ID 后终止进程。

仅满足以下条件的工具会被注册：服务启用、工具名称在服务 `allowed_tools` 内、工具 schema 为 JSON 对象。注册名固定为 `mcp__<server_id>__<tool_name>`，避免不同 MCP 服务与内置工具重名；模型描述中保留原始服务名与工具名。

调用时向 MCP 传递 `{ name: 原工具名, arguments: 模型参数 }`。MCP JSON-RPC error、超时、异常退出和无效结果统一转为 `ToolInvocationError`，不会中断 Agent 循环。

## 写操作确认

工具元数据的 `annotations.readOnlyHint` 为 `false` 或缺失时按写操作处理；`true` 视作只读。注册时，将写工具包装为“确认前不可执行”的工具。

当模型发起写工具调用，Agent 输出新的 `tool_approval_requested` 事件，内容包括调用 ID、服务器名、原始工具名和参数；本轮暂停，不启动 MCP 子进程。前端在聊天流中显示确认卡片，用户可批准或拒绝。

批准后，前端调用新增确认 API，由服务器在对应会话中执行已挂起调用并继续 Agent 循环；拒绝时写入拒绝结果给模型并继续循环。挂起调用仅保存在内存中、绑定会话和调用 ID，重启后失效；重复确认返回安全错误。

## 启动与数据流

`build_application` 创建 `McpCenterService` 后发现工具并注册适配器，再将已填充的 registry 注入 `AgentLoop`。发现失败的单个服务被记录并跳过，不阻断应用启动或其他服务。

聊天流现有 NDJSON 增加 `tool_approval_requested` 事件；前端 `useChat` 暂停当前流并显示批准/拒绝操作。确认请求返回继续产生的 NDJSON，沿用现有事件渲染与会话持久化逻辑。

## 安全与错误处理

- 只使用已保存的 `command` 与 `args`，不经 shell 拼接执行。
- 严格执行启用和白名单检查；运行时再检查一次。
- 有限超时并始终终止子进程。
- MCP 返回内容仅作为工具结果，不作为可执行配置。
- 写操作绝不在确认前启动子进程；拒绝结果明确告知模型。

## 验收与测试

后端测试覆盖：工具发现的白名单/命名空间、JSON-RPC `tools/call` 参数和结果、超时/错误映射、启动时注册、只读直接调用、写工具等待批准、批准/拒绝后 Agent 继续。

前端测试覆盖：收到确认事件显示服务器/工具/参数；批准和拒绝发送正确请求；流继续后消息、工具状态正常更新。

使用 Browser MCP 的只读工具进行端到端验证。执行完整 Python 测试、前端测试和生产构建。
