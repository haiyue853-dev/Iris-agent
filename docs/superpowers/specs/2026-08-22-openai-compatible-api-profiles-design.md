# OpenAI 兼容 API 多配置档案设计

## 目标

将当前只能维护一套模型 API 参数的设置，改造成可保存、测试并切换多套 OpenAI 兼容 API 配置的档案管理功能。用户可以接入 DeepSeek、OpenRouter、硅基流动、Ollama、LM Studio 或其他提供 OpenAI 兼容接口的服务，而不需要修改程序代码。

首版只支持 OpenAI 兼容协议，不实现 Anthropic 或 Gemini 原生协议。API Key 允许为空，以支持无需认证的本地模型服务。

## 配置档案

每套档案包含：

- 稳定且不可变的档案 ID；
- 用户可编辑的显示名称；
- Base URL；
- API Key，可为空；
- 模型名称；
- 是否为当前启用配置；
- 最近一次连接测试的状态与时间，仅作为提示，不作为保存前提。

系统至少保留一套档案，同时只能有一套当前配置。删除当前配置前必须先切换到另一套配置。

## 兼容与迁移

首次读取多配置存储时，如果尚无档案，则从现有 `OPENAI_BASE_URL`、`OPENAI_API_KEY` 和 `LLM_MODEL` 创建一套名为“默认配置”的档案。迁移不删除原有 `.env` 字段；如果多配置文件不可用，启动逻辑仍可回退到旧字段。

迁移必须幂等：多次启动不会重复创建默认档案。现有 API Key 不会显示或返回给前端。

## 存储与安全

多配置存储在项目本地的独立配置文件中。保存采用同目录临时文件写入后原子替换，避免中断造成半写入文件。存储层负责校验配置结构、保证唯一 ID、保证唯一当前项，并隔离文件读写细节。

后端响应只包含 `api_key_set` 和掩码值，不返回 API Key 明文。日志、异常响应和测试连接结果不得包含 Key、认证头或完整上游响应正文。

配置文件属于本地敏感数据，应加入忽略规则，不进入版本控制；仓库只保留不含密钥的示例结构。

## 后端架构

将职责拆分为三个边界清晰的单元：

1. 配置档案存储：负责加载、迁移、校验和原子保存。
2. 配置服务：负责增删改、连接测试、当前配置约束，以及将档案转换为运行时模型配置。
3. HTTP API：负责请求校验、掩码响应和稳定错误码，不直接操作文件或模型客户端内部属性。

设置 API 提供：

- 获取全部配置档案和当前档案 ID；
- 新增档案；
- 更新档案；
- 删除非当前档案；
- 测试指定表单参数或已保存档案；
- 将指定档案设为当前配置。

设为当前配置时创建新的 OpenAI 兼容客户端和 Provider，并通过服务的受控入口替换后续请求使用的 Provider。已经开始生成的请求保留它启动时持有的 Provider，不在执行中途切换。

## 连接测试

连接测试使用表单中尚未保存的值或已保存档案的值，发送一个输出上限很小的请求，并设置较短超时。API Key 可为空；为兼容要求非空 Key 的 SDK，可仅在客户端内部使用不会暴露的占位值，但不得写回用户配置。

结果使用稳定错误类别：

- Base URL 格式错误；
- 无法连接或超时；
- 认证失败；
- 模型不存在或无权访问；
- 上游服务错误；
- 连接成功。

连接测试失败不阻止保存，也不阻止用户主动设为当前，但界面必须明确显示最近测试未成功或尚未测试。

## 前端交互

设置弹窗沿用项目现有黑、白、灰主题、圆角、字体和紧凑间距，不新增彩色状态语义。

布局为左侧档案列表、右侧编辑区：

- 左侧显示配置名称、模型名称和唯一的当前标记，并提供新增入口；
- 右侧编辑名称、Base URL、API Key 和模型名称；
- API Key 已设置时显示掩码，输入留空表示保留旧值；新建本地配置时可保持为空；
- 操作包含测试连接、保存、保存并设为当前、删除；
- 当前状态使用黑色实心标记、图标和文字共同表达，不依赖颜色；
- 小屏幕下改为上下布局，档案列表横向滚动或使用紧凑选择器，保证表单可输入。

新增配置可提供常见服务名称与 Base URL 的填充建议，但预设只负责填充，所有字段仍可编辑，也允许完全自定义服务。

## 错误处理

- 配置文件损坏时不覆盖原文件，返回可理解的本地配置错误，并保留 `.env` 回退能力；
- 写入失败时维持上一个有效运行时 Provider，不出现“界面显示已切换但运行时未切换”的状态；
- 运行时切换失败时不更新当前档案标记；
- API 使用稳定错误码，前端展示简短中文信息；
- 并发保存通过存储层串行化，避免互相覆盖。

## 测试与验收

后端测试覆盖：

- 旧 `.env` 首次迁移及幂等性；
- 档案的新增、读取、更新与删除；
- 唯一当前项和禁止删除当前项；
- 原子保存失败后的状态保持；
- API Key 掩码、不回传明文和空 Key；
- Base URL 与模型名校验；
- 测试连接的成功、认证失败、模型错误、连接失败和超时；
- 切换后新请求使用新 Provider，已运行请求不被改变。

前端测试覆盖：

- 档案列表与当前状态；
- 新增、编辑、切换和删除限制；
- API Key 留空时的保留语义；
- Base URL、名称和模型字段校验；
- 测试连接与保存反馈；
- 小屏幕布局和黑白灰状态表达。

完成标准：后端完整测试、前端测试、生产构建和 lint 均通过，并在本地设置页实际完成新增两套配置、测试连接、切换当前配置和发起聊天验证。

## 范围外

- Anthropic、Gemini 等原生协议；
- 一个档案下维护多个模型并在聊天页逐条选择；
- 云同步、多用户配置共享或操作系统钥匙串集成；
- 自动发现服务端模型列表；
- 自动判断第三方服务是否完全符合 OpenAI 协议。
