# 热点雷达站内通知设计

## 目标

让热点雷达在发现新增匹配项时主动留下站内通知，并让用户能查看每次自动化扫描的完整结果；不接入外部消息渠道。

## 范围与规则

- 仅当一次扫描新增热点数量大于零时创建通知；零命中和来源失败不创建通知。
- 通知记录任务、扫描摘要、命中数量和关联热点条目；支持列表读取、标为已读和删除。
- 自动化执行记录保存扫描摘要、命中数量、失败来源和新增热点 ID；手动执行与计划执行使用同一记录结构。
- 前端在自动化任务中心内展示未读通知和可展开的执行详情，不增加独立页面。
- 热点条目仍保留在现有雷达存储中；通知只存条目 ID，避免复制内容并保持数据一致。

## 数据与服务边界

新增 `NotificationService`，以独立 JSON 文件存储通知，提供创建、列表、已读和删除操作。`AutomationService` 在扫描完成后基于 `ScanResult` 生成执行详情，并仅在 `new_count > 0` 时调用通知服务。`HotRadarService.scan()` 扩展返回新增条目 ID，供两个服务关联。

## API

- `GET /api/notifications`：返回通知，未读优先。
- `PUT /api/notifications/{id}/read`：标记已读。
- `DELETE /api/notifications/{id}`：删除通知。
- `GET /api/automation/tasks/{id}/executions`：在既有响应中增加 `new_count`、`failed_sources`、`item_ids`。

## 前端体验

任务中心顶部展示通知摘要与未读数；通知卡可展开查看命中热点链接，并可标记已读或删除。任务行加入“执行详情”开关，显示最近三次扫描的状态、命中数量、失败来源与摘要。沿用现有卡片、边框和强调色。

## 错误与恢复

通知存储采用原子替换写入。若通知写入失败，不回滚已完成扫描或执行账本：执行仍为成功，错误仅记录到服务日志。应用启动不应因已有通知文件损坏以外的通知问题阻断。

## 验证

后端测试覆盖新增热点创建通知、零命中不创建通知、已读/删除 API 与执行详情字段。前端测试覆盖未读通知显示、标记已读、详情展开和热点链接。最后运行完整 Python 套件、目标 Vitest 套件与 Vite 生产构建。
