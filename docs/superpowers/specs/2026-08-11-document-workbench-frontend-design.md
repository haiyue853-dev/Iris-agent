# 文档工作台前端设计

## 目标与范围

将现有“文档工作台”占位页替换为可用界面，直接对接已完成的本地优先后端：资料上传、解析状态查看、资料选择、草稿生成、草稿编辑与带版本号保存，以及 Markdown / Word 导出。

本次不改动后端接口、不新增流式生成，也不调整 MCP、热点雷达或 AI 日报功能。

## 页面结构

桌面端采用三栏工作区，并沿用 AI 日报工作台的响应式模式：

1. 左栏“资料库”：上传区、文件列表与解析状态。每个文件可选为生成来源，失败文件可删除；`pending` 禁止选择，`ready` 可选择，截断结果有明确提示。
2. 中栏“生成”：展示四种模板（会议纪要、PRD、技术方案、周报）、可选资料计数、补充说明和生成按钮；下方显示草稿列表，点击加载对应草稿。
3. 右栏“编辑与导出”：标题输入、Markdown 正文编辑器、保存状态、保存/重试控件及 Markdown、Word 导出入口。

在窄屏下，三栏切换为“资料 / 生成 / 编辑”标签页；当前草稿在切换间保持不丢失。

## 前端数据边界

新增 `api/documents.ts` 作为唯一 HTTP 客户端，统一解析 API 错误，提供：列出/上传/删除资料、列出/生成/读取/保存草稿和导出 URL。

在 `types.ts` 定义文档、来源、引用、模板与草稿类型。`useDocumentWorkbench` 维护页面状态：资料、选中资料 ID、草稿列表、当前草稿、编辑中的标题/正文、加载/生成/上传/保存状态与错误消息。

首次进入加载资料和草稿。上传成功后刷新资料；删除已选资料时同步取消选中。生成前必须至少选择一个 `ready` 资料，成功后将新草稿置为当前并切至编辑页。草稿列表按后端顺序显示。

## 保存与冲突处理

编辑只更新本地草稿。保存使用 `expected_revision`。成功响应替换当前草稿并显示“已保存”。收到 409 时，不覆盖本地编辑：保留文本、标记“版本已冲突”，并提供“重新加载最新版本”操作；用户可在重新加载前复制或继续编辑本地内容。

保存中的请求禁用重复保存、草稿切换、生成与删除操作。非冲突错误显示可重试提示且保留编辑内容。

## 组件职责

- `DocumentWorkbenchPage`：组合工作区、移动端标签和共享错误条。
- `DocumentLibrary`：上传、资料状态、选择与删除。
- `DocumentComposer`：模板与说明输入、生成、草稿列表。
- `DocumentEditor`：标题/Markdown 编辑、保存、冲突恢复和导出。
- `useDocumentWorkbench`：页面状态与异步操作；不包含呈现逻辑。

样式加入 `App.css`，复用当前主题变量、按钮、卡片和工作区响应式约定；不引入编辑器或 Markdown 渲染的新依赖。

## 验收与测试

前端测试覆盖：从侧栏进入工作台；资料状态与选中规则；生成请求参数与成功后加载草稿；保存成功、失败与 409 冲突；导出链接；窄屏标签切换。

执行 `npm run test` 和 `npm run build`。后端不变更，因此保留现有 Python 测试作为回归检查。
