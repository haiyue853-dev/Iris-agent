# MCP 可观测性设计

## 目标

提供 MCP 服务最近检测与工具调用的可诊断状态，同时避免记录敏感数据。

## 数据边界

每条事件只包含：服务 ID、事件类别（`discovery` 或 `tool_call`）、工具名（仅调用事件）、结果、耗时毫秒和时间戳。绝不记录请求参数、工具返回值、命令参数、环境变量或错误原文。日志仅存于进程内，最多 50 条，进程重启即清空。

## 数据流

`McpCenterService` 在 `discover_tools()` 与 `call_tool()` 的 finally 路径记录成功或失败事件。只读 API 返回指定服务的最近事件。MCP 管理页加载服务后并行加载其日志，在卡片内展示最后一次检测与最近调用摘要。

## 失败处理

日志写入不影响 MCP 操作；未知服务日志请求返回 404。检测失败仍会留下失败事件，方便修正启动命令。
