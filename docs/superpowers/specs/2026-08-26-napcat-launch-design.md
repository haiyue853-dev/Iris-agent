# NapCat 一键启动设计

## 目标

在消息渠道页面配置 NapCat 可执行文件路径，并通过按钮由 Iris 后端启动 NapCat，减少 QQ 接入时手动打开客户端的步骤。

## 方案

- 后端新增 NapCat 控制服务，负责读取/保存本地路径、校验文件和启动进程。
- 配置保存于 `data/gateway/napcat.json`，与 `agent.yaml` 中的 QQ WebSocket 设置分离。
- 启动接口仅接受本机绝对路径；路径必须存在且为文件，启动时使用 `subprocess.Popen`，不经过 shell。
- 服务记录最近启动的进程句柄。进程仍在运行时重复点击返回已运行状态，不重复创建进程。
- 消息渠道 API 提供状态、保存路径和启动接口；前端展示路径输入、保存按钮、启动按钮及错误/成功提示。
- 启动失败、路径无效和权限错误转换为稳定的 API 错误码与中文提示。

## 测试

- 后端覆盖默认路径、路径保存、无效路径、已运行进程和启动失败。
- 前端覆盖路径回填、保存请求、启动请求及按钮状态。
