# MCP 失败提示与重新检测设计

## 目标

当 MCP 服务最近一次连接检测或工具调用失败时，在连接中心显示可操作、无敏感信息的失败摘要，并将现有检测按钮明确为重新检测入口。

## 安全数据边界

每条失败事件新增可选 `failure_kind`，仅允许：`startup_failed`、`timeout`、`protocol_error`、`tool_error`、`unknown`。不保存原始异常文本、请求参数、工具结果、环境变量值或命令参数。

`McpCenterService` 在已知边界将异常归类：子进程无法启动为 `startup_failed`，读取超时为 `timeout`，JSON-RPC 响应或 MCP 错误为 `protocol_error`，工具声明 `isError` 为 `tool_error`，其他受控失败为 `unknown`。历史事件缺失该字段时保持兼容。

## 页面行为

每张 MCP 服务卡片从最近活动中取第一条失败事件。存在失败时，在活动区顶部显示“最近操作失败”的提示、失败类别对应的固定中文说明和“重新检测连接”按钮文案；不存在失败时维持“检测连接”。点击两种按钮均调用既有发现接口，成功后刷新该服务的事件和工具列表，使失败提示消失；失败时保留最近事件并展示现有全局请求错误。

失败提示只使用 `failure_kind` 映射的固定文本，不渲染服务端异常消息。不会修改白名单、审批、工具调用或持久会话规则。

## 验收

- 后端事件在失败时持久化安全分类，重启后仍可读取，且不含敏感字段。
- API 继续返回安全事件字段。
- 前端针对失败事件展示固定摘要与“重新检测连接”；点击后调用既有发现接口，成功刷新后恢复普通按钮文案。
- MCP 后端测试、MCP 页面 Vitest、前端构建和后端全量测试通过。
