# GPT-SoVITS 情绪朗读与延迟优化设计

## 背景与目标

Iris Agent 已能在助手消息下方按需生成并播放高松灯中文语音，但首次点击需要等待模型启动和权重加载，长回复的推理期间也缺少清晰的阶段反馈；当前固定使用一条参考音频，所有回复的语气趋同。

本次优化实现两项目标：

1. Iris 启动后在后台预热 GPT-SoVITS，减少用户首次点击的等待时间，并为生成阶段提供明确的超时与错误反馈。
2. 从 `D:\AI\KiraKsm\tomori\tomori_mp3` 的 384 条日语台词中建立高松灯情绪参考库，根据每条助手回复自动选择合适的参考音频，让中文朗读更有感情。

## 范围与原则

- 第一版不重新训练 GPT/SoVITS 权重。GPT-SoVITS 的情感主要由参考音频和参考文本引导；把不同情绪的素材混在一起重训并不能提供稳定的可控情绪，还可能削弱现有音色。
- 保留当前已授权的 `MyGO_高松灯_v2pp` 权重，只建立和使用情绪参考音频索引。若验收后个别情绪仍不明显，再单独评估微调训练。
- 情绪选择全自动完成，不在聊天气泡中增加手动选择器，不自动播放语音。
- 音频和模型继续保留在 `D:\AI`，仓库只保存索引、配置及代码，不复制原始素材。
- 所有分类结果允许人工修改，自动分类永远不覆盖用户手工确认的条目。

## 情绪类别

首版采用四类，既覆盖日常对话，也避免样本过细导致选择不稳定：

| 类别 | 使用场景 | 台词线索 | 声学倾向 |
| --- | --- | --- | --- |
| `neutral` 平静 | 说明、回答、叙述 | 普通陈述、停顿适中 | 中等音高、能量和语速 |
| `happy` 开心 | 祝贺、感谢、积极回应 | 感叹、肯定、开心词语 | 较高音高和能量、语速稍快 |
| `sad` 悲伤 | 道歉、遗憾、安慰、失落 | 否定、道歉、省略号 | 较低能量、语速偏慢、停顿较多 |
| `tense` 紧张/害羞 | 犹豫、惊讶、担心、被追问 | 问号、重复、语气词、断续文本 | 音高波动较大、短促或停顿明显 |

无法可靠判断时回退到 `neutral`。情绪只影响朗读方式，不改变 Agent 的文字内容。

## 参考音频索引生成

新增一个可重复运行的本地索引命令，扫描配置的素材目录：

1. 以 MP3 文件名（去除扩展名）作为日语 `prompt_text`，因此不依赖额外台词文件。
2. 排除过短、过长、空白、损坏或解码失败的音频；参考音频优先保留约 2～10 秒的清晰单句。
3. 使用 GPT-SoVITS 整合包内的 `ffprobe.exe`/`ffmpeg.exe` 读取时长并提取基础声学统计，如响度、语速近似值、停顿比例和音高变化。分析失败时仍可仅按台词规则分类。
4. 根据日语台词中的标点、语气词和情绪关键词产生文本分数，再与声学分数合并得到类别及置信度。
5. 每类选出若干高置信度、时长合适且声音质量较好的候选，不只依赖一条音频；同时保留当前已验证的参考音频作为 `neutral` 强制回退。
6. 将结果原子写入 `data/tts/emotion_references.json`，记录素材路径、台词、类别、置信度、时长、文件修改时间和 `manual` 标记。

索引按素材路径、大小和修改时间增量更新。用户手工修改类别并设置 `manual: true` 后，后续重建索引保留该分类。

## 回复情绪判断与参考选择

运行时不调用额外大模型，以避免增加网络依赖和等待时间。`EmotionClassifier` 对清洗后的中文回复执行轻量规则评分：

- 开心：祝贺、感谢、成功、喜欢、太好了等词语及积极感叹句。
- 悲伤：抱歉、遗憾、难过、失去、可惜、安慰等表达。
- 紧张/害羞：担心、害怕、怎么办、没关系吗、连续问号或较多犹豫表达。
- 其余为平静；冲突时按最高分选择，分数不足时回退平静。

`EmotionReferenceSelector` 从对应类别选择主参考音频，并可传入同类别最多两条辅助参考音频进行音色/语气融合。选择优先级为：人工确认、高置信度、合适时长、近期未使用。固定种子保证同一条消息在配置不变时结果稳定，缓存可重复命中。

缓存键新增情绪类别、主参考与辅助参考文件身份、推理参数。参考音频或索引变化后自然生成新缓存，不误用旧语气。

## GPT-SoVITS 调用参数

客户端按选择结果动态发送：

- `ref_audio_path`：所选情绪的主参考音频。
- `prompt_text`：主参考音频的日语文件名台词。
- `prompt_lang: ja`、`text_lang: zh`。
- `aux_ref_audio_paths`：同类的 0～2 条辅助参考音频；若当前整合包不支持或请求失败，则只用主参考重试一次。
- 推理参数先保持当前已验证值，避免用高 `temperature` 冒充情绪控制。只在真实试听后微调 `speed_factor`、`top_k`、`top_p` 和 `temperature`。

正文仍会在提交前剔除 GPT-SoVITS Windows 控制台无法用 GBK 编码的字符（如 emoji），避免上游在日志输出阶段崩溃。

## 后台预热与生成状态

Iris 完成后端启动后，通过独立后台线程调用现有进程管理器：

1. 检查 9880 健康状态。
2. 必要时启动 GPT-SoVITS 子进程。
3. 加载配置的 GPT 与 SoVITS 权重。
4. 标记 TTS 为 `starting`、`ready` 或 `failed`。

预热不阻塞 Iris API 和页面打开。首次点击发生在预热期间时，请求复用同一启动任务，不重复启动进程；发生在预热失败后时允许按现有流程重试。Iris 自己启动的 GPT-SoVITS 仍随 Iris 退出，用户单独启动的服务仍只复用、不关闭。

后端新增只读 TTS 状态端点，前端按钮按阶段显示：

- `正在启动语音模型…`
- `正在合成（平静/开心/悲伤/紧张）…`
- `正在朗读`
- 超时或失败后的中文错误与“重试”操作

前端请求使用可取消控制器；组件卸载或用户主动取消时停止等待。后端保留推理串行锁，防止并发请求造成显存不足。生成超时返回现有 `504`，不让按钮无限旋转。

## 配置变更

在现有 `tts` 配置中增加：

```yaml
tts:
  warmup_on_startup: true
  emotion_enabled: true
  emotion_audio_directory: D:/AI/KiraKsm/tomori/tomori_mp3
  emotion_index_file: data/tts/emotion_references.json
  emotion_aux_reference_count: 2
  request_timeout_seconds: 300
```

索引不存在时，应用启动阶段自动构建一次；若自动构建失败，则记录原因并回退到当前固定参考音频，普通文字对话不受影响。配置关闭 `emotion_enabled` 后完全保留原有固定参考行为。

## 错误处理与可观测性

- 素材目录不存在、索引为空或某一类没有可用音频：回退固定参考，不阻断朗读。
- 单个文件损坏：跳过并记录文件名，不让整个索引失败。
- 辅助参考不兼容：只用主参考重试一次。
- 模型启动或推理超时：返回明确阶段和可重试错误；后台任务不吞掉异常。
- 日志记录预热耗时、推理耗时、缓存命中、所选情绪和参考音频文件名，但不记录完整聊天隐私内容。

## 测试与验收

### 自动化测试

- 素材扫描、文件名台词提取、损坏文件过滤、增量索引和人工分类保留。
- 四类台词规则、冲突评分、低置信度回退以及中文/日文标点。
- 参考选择稳定性、人工条目优先、辅助参考上限和类别缺失回退。
- 动态 GPT-SoVITS 请求参数、辅助参考失败降级和情绪感知缓存键。
- 后台预热不阻塞应用启动、并发复用、失败后重试和仅关闭自有进程。
- 前端预热/合成/播放/错误/取消状态以及原有单音频播放约束。

### 真实验收

1. 对 384 条素材重建索引，四类均有可播放候选，随机抽听每类至少三条并核对分类。
2. 冷启动 Iris，页面可立即打开；后台完成权重加载后点击朗读，不再承担模型启动时间。
3. 分别用平静说明、开心祝贺、悲伤安慰、紧张疑问四条中文回复生成 WAV，日志显示匹配类别，试听能感知语气差异且仍保持高松灯音色。
4. 同一消息再次朗读命中缓存并快速播放；长回复超时或 GPT-SoVITS 异常时按钮停止旋转并显示可重试错误。
5. 情绪索引不可用时仍能用原固定参考音频合成，且设置档案和历史会话不受 TTS 生命周期影响。

## 后续训练判定

第一版真实试听后，只有在某一类别的参考引导仍持续不明显时才进入训练阶段。训练将使用单独的数据清洗与备份流程，并保留当前可用权重，不覆盖原文件。是否训练、使用哪些片段及输出权重名称需再次确认，不属于本次实现范围。
