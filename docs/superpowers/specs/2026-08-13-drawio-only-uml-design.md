# Draw.io 独占 UML 工作台设计

**日期：** 2026-08-13  
**状态：** 已确认，待审阅实现计划

## 目标

将 UML 工作台收敛为唯一的 Draw.io 专业画布，移除已不可达但仍参与前端编译的 React Flow 旧画布，降低包体积与维护成本，同时保持当前用户可见的 UML 生成、编辑、保存和导出能力。

## 背景与决策

`UmlFlowPage` 当前将编辑器模式固定为 `professional`。因此 React Flow 的经典画布分支虽然仍被编译和打包，但不会被用户访问；Draw.io 已是实际使用的工作流。

考虑过三个方案：

1. 保留两个编辑器并恢复模式切换：功能覆盖最多，但维护两套画布，且与当前产品方向不符。
2. 保留 React Flow 代码、仅隐藏入口：改动最小，但包体积和不可达代码问题仍然存在。
3. 彻底移除 React Flow，仅保留 Draw.io：职责最清晰，能消除无效依赖和样式。采用此方案。

## 保留的用户体验

- 选择图表类型、输入需求并由 AI 生成 Mermaid 源码。
- 编辑当前 Mermaid 源码，并将其导入或重新导入 Draw.io。
- 在 Draw.io 中持续编辑，自动保存本地 Draw.io 图表状态。
- 导出 PNG、SVG、XML，并复制或下载 Mermaid 源码。
- 现有应用导航保留 UML 页面实例，避免在切换页面时丢失 Draw.io iframe 的编辑上下文。

## 变更边界

### 删除

- `UmlFlowPage` 内全部 React Flow 经典画布状态、分支、快捷键和导出逻辑。
- 仅被旧画布使用的 Flow 组件、属性面板、形状面板、右键菜单、Mermaid 解析器及旧画布导出模块。
- 与旧画布对应的 CSS，包括 React Flow 选择器和 Flow 节点、边、面板样式。
- `@xyflow/react` 依赖；若仓库内无剩余运行时导入，同时移除仅为旧画布渲染而安装的 `mermaid` 前端依赖。

### 不删除或不迁移

- Draw.io 编辑器、其存储模块和相关测试。
- 后端生成的 Mermaid 文本协议；Draw.io 继续接收 Mermaid 文本导入。
- 用户浏览器中旧 React Flow 本地存储的数据。应用不再读取它，但不会主动清除，避免误删历史数据。
- 与 UML 无关的未跟踪文件、临时目录和既有本地变更。

## 组件边界与数据流

`UmlFlowPage` 只负责编排：收集需求、调用生成接口、保存 Mermaid 源码、发出 Draw.io 导入请求，并展示生成/导入状态。

`DrawioEditor` 继续负责 iframe 通信、Draw.io 本地保存和 PNG/SVG/XML 导出。它不依赖 React Flow，也不解析旧画布数据。

```text
用户需求 → UML 生成接口 → Mermaid 文本 → UmlFlowPage
                                      ↓
                           DrawioEditor 导入 / 编辑 / 导出
```

## 失败处理与兼容性

- AI 生成失败继续显示现有错误提示，不创建空图表。
- Draw.io 尚未就绪时，保留现有导入状态与重新导入入口，不伪造导入成功。
- 移除后不再提供 React Flow 经典画布切换，也不对旧画布数据做自动迁移；这是有意的产品收敛，而非兼容性故障。

## 验收标准

1. 前端源码和 `package.json` 不再包含 `@xyflow/react`，仓库中不存在旧画布组件的引用。
2. UML 页面仍可生成 Mermaid、编辑源码并导入 Draw.io。
3. Draw.io 的自动保存及 PNG、SVG、XML 导出测试继续通过。
4. UML 页面测试覆盖专业画布的导入行为，前端生产构建通过。
5. 删除旧样式后，现有 Draw.io 工作台的主题、排版和可读性不退化。
