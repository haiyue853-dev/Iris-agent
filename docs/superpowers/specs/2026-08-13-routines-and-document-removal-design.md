# 自动化任务中心与文档工作台移除设计

## 目标

彻底移除不再需要的“文档工作台”，以 Hermes 的例程（Routines）模式新增 Iris 自动化任务中心。首版让既有的 AI 日报和热点雷达能够按计划运行，并保留可审计的执行记录。

## 范围与删除边界

文档工作台会完整移除：

- 前端 `documents` 页面、Hook、API 客户端、组件、样式和关联测试。
- 后端 `iris_agent.documents` 包、`/api/documents` 路由、请求模型、应用服务注入、配置项和关联测试。
- Skill 中心的 `document-workbench` 内置 Skill、允许的 `documents` 入口和关联测试。
- 当前 `data/documents` 目录内的资料、提取结果、索引和草稿数据。
- 过往“文档工作台前端”设计与实现计划文档。

不删除 AI 日报的附件、版本、工作记录或对话数据；它们由 `reports` 和附件模块独立管理。

## 自动化任务中心 MVP

### 用户界面

侧栏以“自动化任务”替代“文档工作台”，沿用现有 Iris 浅灰侧栏和 MCP 页面卡片样式。

任务中心提供：

- 概览：启用任务数、最近成功运行、待处理失败数。
- 任务列表：名称、目标、启停状态、计划、上次及下次运行时间。
- 操作：创建、编辑、启用、暂停、立即执行、查看运行记录。
- 运行记录：任务触发时间、开始/结束时间、状态、结果摘要和失败原因。

首版只允许热点雷达扫描这一安全目标。AI 日报自动草稿依赖尚未定义的汇总规则，本次保持手动；不会自动执行 MCP 工具，也不会接入外部消息推送。

### 数据模型与持久化

新增 `automation` 模块并在 `data/automation` 使用 JSON 原子写入保存任务与执行记录。

任务至少保存：稳定 ID、名称、目标类型、启用状态、时区、计划表达式、创建/更新时间及下次运行时间。执行记录使用独立 ID，保存任务 ID、触发来源（计划或手动）、`pending/running/succeeded/failed/unknown` 状态、时间戳和安全的结果/错误摘要。

运行记录为追加式；终态不可被后续调度覆盖。重启时，遗留的 `running` 记录标记为 `unknown`，不会盲目重试可能产生副作用的动作。

### 调度与执行

应用启动后加载启用任务，并以 Asia/Shanghai 时区计算下一次运行。调度器先创建并持久化执行记录，再执行目标；同一任务同一计划窗口只能成功声明一次，避免重复运行。手动运行复用同一执行管线并记录 `manual` 触发来源。

本次先完成热点雷达的关键词订阅、资讯抓取适配、去重、摘要归档和只读扫描，再让任务中心调用该能力。AI 日报不修改或自动发布，保持现有手动工作流。

### API

新增 `/api/automation/tasks` 用于任务列表与创建；任务详情、更新、删除、启停及立即执行使用任务 ID 子路径；`/executions` 返回分页或上限受控的执行记录。所有请求模型执行严格字段验证，错误通过既有 API 错误格式返回。

## 错误、安全与迁移

- 无效计划、未知目标、重复执行声明和不可用目标都返回明确错误。
- 任务执行不会读取或显示 API Key、MCP 环境变量或工具参数中的秘密。
- 删除 `data/documents` 前由实现步骤做目标路径存在性与绝对路径确认，仅针对该目录递归删除；不会使用通配符或影响 `data/reports`。
- 现有用户未跟踪文件 `PROJECT_STATUS.md`、`web-react/src/tmp_c.py`、`.pytest_tmp` 与 `.basetmp_*` 不属于本任务，保持不动。

## 验证

完成后运行后端全量测试、前端测试和生产构建；在本地浏览器验证侧栏替换、任务创建/暂停/立即执行与执行记录展示。
