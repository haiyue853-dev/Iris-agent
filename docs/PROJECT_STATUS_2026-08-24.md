# Iris Agent 项目状态（2026-08-24）

## 1. 已完成内容

- 主对话：NDJSON 流式回复、停止、任务中心、失败状态保留、消息重新生成兼容修复。
- 工具：文件读写、命令执行、网页搜索/抓取、记忆回忆、MCP、子任务、技能等工具接入；工具失败卡片显示在回复顶部。
- 稳定性：启动脚本会释放 8000 端口；流式首字超时和首次请求重试；前端/后端的跨域与本地启动链路已处理。
- 性能：避免普通问候调用工具；快照类工具（搜索、回忆、时间）同一请求只暴露一次；系统提示要求最短工具路径。
- 对话模式：输入框提供“快速 / 思考”模式，不切换模型，仅影响本次任务的回答和工具策略。
- 本地知识库 RAG：资料导入、集合创建/重命名/删除、文档管理、分块、向量/关键词/图谱多路召回、重排、引用、评测、导出导入、重复检测与图谱审计。
- 图谱：实体/关系抽取、可视化、拖动节点、关系编辑、实体重命名/删除、合并与摘要。
- 前端：灰白黑主题、侧边栏折叠、知识库页面、任务中心、MCP、自动化、热榜、日报、UML 等页面已接入。
- 输入框知识库菜单：支持不开启、全部知识库或指定知识库；启用后高亮并在请求中携带选择范围。

```text
│  ├─ api/                 # FastAPI 路由、请求模型

│  ├─ mcp_center/          # MCP 服务配置、发现和调用
│  └─ task_* / subagent/   # 任务队列、任务中心与子代理
├─ web-react/src/
│  ├─ components/          # 聊天、知识库、侧栏、设置等 UI
│  ├─ components/assistant-ui/ # 输入框、消息、工具卡片、引用展示
│  ├─ api/                 # 前端 API 客户端
│  ├─ hooks/ lib/          # 会话状态与 assistant-ui 运行时适配
│  └─ App.tsx              # 页面路由和全局聊天状态
├─ data/                   # 会话、知识库、设置、任务等本地数据
├─ tests/                  # 后端 pytest 测试
├─ agent.yaml              # 默认运行配置与系统提示
├─ start.ps1 / start.cmd   # 本地启动入口
└─ server.py               # FastAPI 启动入口
```

## 4. 未解决问题与风险

- 模型响应速度仍受当前已激活的第三方模型服务影响；代码只能减少多轮工具调用，不能消除服务商首字延迟。
- “快速 / 思考”是通用提示策略，不是所有模型原生支持的推理开关；不同模型的实际表现会不同。
- 输入框知识库菜单近期多次调整，建议做一次浏览器端完整交互回归：不开启、全部库、指定库、刷新后状态。
- 当前工作树有大量未提交修改；尚未整理为一个可回滚的提交点。
- 前端生产包约 1.56MB，Vite 仍提示大包警告；可通过路由级懒加载继续降低首屏负载。
- 图谱实体质量依赖本地抽取模型与资料质量，仍需要在真实资料上持续校正和评测。

## 5. 下一步建议

1. 完成输入框工具区交互收尾：知识库菜单状态、联网开关、模型选择菜单、快速/思考菜单的统一交互和持久化。
2. 增加性能观测：分别记录模型首字、每个工具、检索、抓取和总耗时；在任务详情中展示。
3. 增加超时降级：模型或工具超时后返回已获得的部分结果，并提供继续/重试操作。
4. 为知识库菜单、流式异常恢复、停止/重新生成添加端到端回归测试。
5. 按页面拆分前端大模块，启用动态导入，减少首屏 JS 体积。
6. 在功能稳定后整理当前改动、运行完整测试并提交 main 分支。
