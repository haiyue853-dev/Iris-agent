# Agent 后端开发岗位面试题整理

> 适用方向：Agent 应用开发、AI 后端开发、Java 后端开发。  
> 重点技术：Agent 核心机制、Spring Boot、MyBatis、MySQL、Redis。  
> 使用方式：先掌握每题的回答主线，再结合自己的项目经历补充实现细节和结果。

## 一、项目定位与自我介绍

### 1. 请介绍一下你的 Agent 项目

**回答主线：**

- 先说项目定位：面向复杂任务的智能 Agent 平台，解决工具调用不可控、执行过程不可见、长任务难以中断恢复等问题。
- 再说核心能力：Agent Loop、工具注册与调用、风险审批、任务状态管理、长期记忆、上下文压缩、知识库检索和执行链路追踪。
- 最后说技术实现：当前项目后端以 Python、FastAPI、OpenAI 兼容模型接口为主，前端使用 React、TypeScript、Vite。

**注意：** 如果面试岗位要求 Spring Boot，可以说明自己正在将相同的领域模型和接口设计映射到 Spring Boot 技术栈，不要把未实际使用的技术说成已经落地。

### 2. 为什么 Agent 不能只做成一个普通的 Chat 接口？

- 普通 Chat 通常是一次请求、一次响应，缺少任务状态、工具执行记录和恢复机制。
- Agent 需要维护消息上下文、工具调用结果、审批状态、失败原因和重试信息。
- 长任务还需要异步队列、取消、断点续跑、幂等和补偿。
- 因此 Agent 更接近一个带模型决策能力的工作流执行系统，而不是简单的问答接口。

### 3. 你的项目中最有技术含量的部分是什么？

建议围绕以下三点回答：

1. 将模型输出转换为可校验、可审批、可追踪的工具调用。
2. 用任务状态、事件记录和幂等控制保证长任务可以暂停、恢复和重试。
3. 通过记忆、上下文压缩和知识库检索控制模型输入质量与 Token 成本。

## 二、Agent 核心高频面试题

### 4. 什么是 Agent Loop？一次循环包含哪些步骤？

典型流程是：

1. 读取系统提示词、历史消息、记忆和当前任务上下文。
2. 调用模型，让模型决定直接回答还是调用工具。
3. 校验模型返回的工具名称和参数 Schema。
4. 判断工具风险，必要时挂起任务等待审批。
5. 执行工具并记录开始、成功、失败或取消事件。
6. 将工具结果追加到上下文，继续下一轮模型推理。
7. 满足终止条件后返回最终答案，并持久化任务状态。

### 5. 如何防止模型生成不存在的工具或错误参数？

- 工具注册表维护统一的名称、描述、输入 Schema 和权限信息。
- 模型返回工具调用后，服务端必须再次校验工具名称、参数类型、必填字段和取值范围。
- 不允许直接执行模型生成的任意函数名或 Shell 命令。
- 校验失败时返回结构化错误，让模型重新规划；连续失败需要设置最大轮数。

### 6. 如何设计工具调用的幂等性？

- 为每次业务动作生成唯一的 `idempotency_token`，由任务 ID、步骤 ID 和动作序号组合生成。
- 执行前先查询 Token 是否已经成功处理。
- 首次执行将 Token 与结果以原子方式写入；重复请求直接返回已保存结果。
- 对外部系统调用时，优先使用对方提供的幂等键；没有幂等能力的操作需要增加补偿或人工审批。
- 幂等记录必须设置合理的生命周期，避免无限增长。

### 7. Saga 补偿和数据库事务有什么区别？

- 数据库事务适合单个数据库内部的原子操作，依赖 ACID 保证一致性。
- Saga 将长流程拆成多个本地事务，每一步成功后继续，后续失败时执行已完成步骤对应的补偿动作。
- Saga 通常只能保证最终一致性，不能假设所有外部操作都能回滚。
- Agent 工具调用涉及文件、第三方 API 或消息系统时，更适合使用“幂等 + 状态记录 + 补偿 + 人工介入”的组合方案。

### 8. 如何设计 Agent 任务状态机？

可以设计为：`queued → running → waiting_approval → running → succeeded`，异常时进入 `failed`，用户取消时进入 `cancelled`。

- 状态变更必须校验合法的前置状态，不能允许任意跳转。
- 每次变更记录事件、操作者、时间、原因和关联步骤。
- 审批通过后只能恢复到被挂起的步骤，不能从头重复执行。
- 状态更新和事件写入要尽量保持原子性。

### 9. 长任务如何实现取消、暂停和恢复？

- 取消请求先写入任务控制状态，再通过取消信号通知执行线程或异步任务。
- 工具执行前、中、后检查取消状态；不可中断的外部调用需要在返回后补偿。
- 任务恢复时读取最后一个已确认成功的步骤和幂等 Token。
- 从断点重新构造上下文，跳过已成功且幂等记录完整的步骤。
- 不能只依赖内存变量，否则进程重启后无法恢复。

### 10. Agent 的记忆和普通聊天历史有什么区别？

- 聊天历史是按时间顺序保存的原始消息，主要服务于当前会话。
- 长期记忆是从多轮对话中提取出的稳定事实、偏好或项目背景，应该分类、可修改、可删除。
- 记忆注入需要设置条目数和字符数上限，防止污染当前上下文。
- 历史过长时，可以将旧消息摘要化，同时保留近期消息和关键事实。

### 11. 如何解决上下文窗口超限？

- 统计字符数或 Token 数，超过阈值后触发压缩。
- 保留系统指令、任务约束、最近若干轮消息和未完成工具调用。
- 将更早的对话压缩成包含目标、决策、事实和待办事项的摘要。
- 对知识库内容和网页内容设置单独长度上限，避免检索结果挤占对话上下文。
- 记录压缩前后的版本，方便排查模型行为变化。

### 12. RAG 流程有哪些关键环节？

1. 文档接入：上传、格式识别、文本解析和清洗。
2. 切分：按标题、段落或 Token 长度切成可检索的 Chunk。
3. 表示：生成 Embedding，同时保留关键词索引。
4. 检索：关键词、向量或混合召回。
5. 重排：根据问题与候选片段的相关性重新排序。
6. 生成：将高相关片段注入提示词并要求模型引用来源。
7. 评估：统计召回率、命中率、答案正确性、引用完整性和延迟。

### 13. 如何降低 RAG 的幻觉？

- 让模型区分“检索到的事实”和“推测内容”。
- 提示词要求只基于给定资料回答，不足时明确说不知道。
- 返回文档标题、Chunk ID 或 URL 等可追溯引用。
- 对检索结果做去重、重排和质量过滤，降低恶意内容污染。
- 使用离线评测集持续检查命中率和拒答准确率。

### 14. Agent 如何实现流式输出？

- 后端将模型 Token、工具开始、工具结束、审批请求和错误统一封装为事件。
- 通过 SSE、WebSocket 或 NDJSON 将事件按顺序推送给前端。
- 每个事件携带任务 ID、会话 ID、步骤 ID 和序号，前端据此重排和去重。
- 连接断开后，客户端使用任务 ID 查询已持久化事件，而不是单纯依赖重新发送请求。

### 15. 如何做 Agent 的安全控制？

- 工具白名单和统一参数 Schema。
- 按工具、参数、资源和用户身份计算风险等级。
- 高风险操作在执行前挂起，等待明确授权。
- 文件路径限制在工作区内，命令执行限制可执行程序和超时时间。
- 对模型输出、网页内容和工具结果做长度限制、敏感信息过滤和审计记录。

## 三、Spring Boot 高频面试题

### 16. Spring Boot 自动配置是如何工作的？

- `@SpringBootApplication` 组合了组件扫描、自动配置和配置类能力。
- 启动时根据 Classpath 中是否存在相关类、配置项和 Bean 条件决定是否装配。
- 自动配置类通过条件注解（如 `@ConditionalOnClass`、`@ConditionalOnMissingBean`）避免覆盖用户自定义 Bean。
- 可以通过配置文件、排除自动配置类或自定义 Bean 覆盖默认行为。

### 17. Spring 中 Bean 的生命周期是什么？

实例化 → 属性注入 → `Aware` 回调 → `BeanPostProcessor` 前置处理 → 初始化方法 → 使用 → 销毁。

常见初始化方式包括 `@PostConstruct`、`InitializingBean` 和自定义初始化方法。面试时要强调：不要在构造阶段依赖尚未注入的字段。

### 18. Spring 依赖注入中构造器注入和字段注入如何选择？

- 优先构造器注入：依赖关系显式、对象创建后就是完整状态，便于测试。
- 字段注入代码短，但隐藏依赖，单元测试和不可变设计较差。
- 多个实现时使用 `@Qualifier` 或 `@Primary` 解决歧义。

### 19. Spring AOP 的应用场景有哪些？

常用于事务、日志、鉴权、监控、限流和审计。

- JDK 动态代理基于接口。
- CGLIB 通过子类代理具体类。
- 同类内部方法调用可能绕过代理，导致事务或切面不生效。

### 20. `@Transactional` 为什么可能失效？

- 方法不是 `public`，或事务注解放在无法被代理识别的位置。
- 同一个类内部直接调用方法，绕过代理对象。
- 抛出异常类型不触发默认回滚，默认主要对运行时异常回滚。
- 数据库引擎不支持事务，或事务方法中开启了异步线程。
- 多数据源、传播级别或事务管理器配置错误。

### 21. Spring Boot 如何处理全局异常？

- 使用 `@RestControllerAdvice` 统一捕获业务异常、参数校验异常和未知异常。
- 返回统一错误结构：错误码、用户可读信息、请求 ID 和时间。
- 不向客户端暴露堆栈、SQL、密钥等内部细节。
- 日志中保留完整异常和链路 ID，便于排查 Agent 工具调用失败。

### 22. 同步接口和异步任务如何选择？

- 短请求、低延迟、结果立即可返回时使用同步接口。
- Agent 长任务、文档解析、批量 Embedding 和外部工具调用适合异步队列。
- 异步接口通常返回任务 ID，客户端通过轮询、SSE 或 WebSocket 获取状态。
- 线程池要设置队列长度、最大线程数、拒绝策略和监控指标。

### 23. Spring Boot 如何设计 SSE 接口？

- 服务端使用 `SseEmitter` 或响应式流持续发送事件。
- 设置心跳、超时、连接关闭和异常回调。
- 事件中携带任务 ID 和递增序号，客户端可以断线续接。
- 长任务状态必须落库，SSE 只负责传输，不应作为唯一状态来源。

## 四、MyBatis 高频面试题

### 24. `#{}` 和 `${}` 有什么区别？

- `#{}` 使用预编译参数，占位符传值，可以防止 SQL 注入，默认优先使用。
- `${}` 是字符串拼接，常用于动态表名、排序字段等场景，但必须使用白名单校验。
- 用户输入不能未经校验直接拼接到 `${}` 中。

### 25. MyBatis 一级缓存和二级缓存有什么区别？

- 一级缓存默认开启，作用域通常是同一个 `SqlSession`。
- 二级缓存作用域更大，需要在 Mapper 和配置中显式启用。
- 写操作可能使缓存失效；分布式部署时要特别关注缓存一致性。
- 对 Agent 任务状态、审批状态等强一致数据，不建议只依赖 MyBatis 缓存。

### 26. MyBatis 中如何实现批量插入？

- 使用 `<foreach>` 拼接多行 `INSERT`，注意单条 SQL 长度和数据库参数限制。
- 使用 `ExecutorType.BATCH` 分批提交，减少网络往返。
- 控制批次大小，失败时明确事务边界和重试策略。
- 大批量导入应记录导入任务状态，避免请求超时后重复写入。

### 27. MyBatis 动态 SQL 有哪些常见问题？

- `where`、`set`、`trim` 使用不当导致多余的 `AND` 或逗号。
- 空集合传给 `foreach` 可能生成非法 SQL。
- 大量动态条件导致 SQL 难以维护，应拆分查询或使用条件对象。
- 排序字段和表名不能直接信任前端参数，必须白名单映射。

### 28. MyBatis 分页如何实现？

- 小数据量可以使用 `LIMIT`，但深分页会出现扫描和回表成本高的问题。
- 深分页可使用基于主键或唯一索引的游标分页，例如 `WHERE id < last_id ORDER BY id DESC LIMIT ?`。
- 分页查询必须有稳定排序，否则翻页时可能重复或遗漏。
- 复杂列表要结合 `EXPLAIN` 检查索引和扫描行数。

## 五、MySQL 高频面试题

### 29. InnoDB 为什么使用 B+ 树索引？

- B+ 树非叶子节点只存索引键，叶子节点存数据或主键，单页能容纳更多键。
- 树高较低，适合磁盘和页式存储。
- 叶子节点有序链表，适合范围查询和排序。
- 联合索引还需要遵循最左匹配原则。

### 30. 什么是聚簇索引和回表？

- InnoDB 的主键索引叶子节点保存完整行数据，属于聚簇索引。
- 普通二级索引叶子节点保存索引列和主键值。
- 通过二级索引找到主键后，再去主键索引查询完整行就是回表。
- 只查询索引中已有字段可以形成覆盖索引，减少回表。

### 31. 联合索引如何设计？

- 将区分度高、使用频繁的等值条件放在前面，再考虑范围条件和排序需求。
- 根据真实 SQL 设计，而不是为每个字段盲目建索引。
- 注意最左匹配、索引下推和覆盖索引。
- 索引不是越多越好，会增加写入、更新和存储成本。

### 32. MySQL 事务的隔离级别有哪些？

从低到高通常是：读未提交、读已提交、可重复读、串行化。

- 读未提交可能出现脏读。
- 读已提交避免脏读，但可能出现不可重复读。
- 可重复读是 InnoDB 常用级别，结合 MVCC 减少不可重复读。
- 串行化通过更强锁保证一致性，但并发能力较低。

### 33. 什么是 MVCC？

- MVCC 通过隐藏字段、Undo Log 和 Read View 保存记录的多版本。
- 普通一致性读根据事务可见性读取历史版本，减少读写阻塞。
- 当前读（如加锁查询）读取最新版本并可能加锁。
- 长事务会阻碍旧版本清理，导致 Undo Log 膨胀。

### 34. 如何排查一条慢 SQL？

1. 使用慢查询日志或监控定位 SQL。
2. 执行 `EXPLAIN`，重点看 type、key、rows、filtered 和 Extra。
3. 检查是否全表扫描、索引失效、回表过多或排序临时表。
4. 优化查询条件、联合索引、返回字段和分页方式。
5. 在接近真实数据量的环境中验证，不只看开发库结果。

### 35. MySQL 中哪些写法容易导致索引失效？

- 对索引列使用函数或计算。
- 隐式类型转换。
- `LIKE '%keyword'` 前置通配符。
- 联合索引跳过左侧列。
- 使用 `OR`、不合理的范围条件或低选择性条件。
- 对列做不必要的类型转换。

### 36. Agent 任务表应该如何设计？

建议至少包含：

- `task_id`、`session_id`、`status`、`priority`、`request_summary`。
- `current_step`、`version`、`created_at`、`updated_at`、`cancelled_at`。
- `last_error`、`retry_count`、`idempotency_token` 或独立幂等表。
- 对 `status + updated_at`、`session_id + created_at`、`priority + created_at` 建立符合查询场景的索引。
- 状态更新使用版本号或条件更新，避免多个 Worker 覆盖彼此结果。

## 六、Redis 高频面试题

### 37. Redis 常见数据类型及使用场景是什么？

- String：缓存、计数器、分布式锁值。
- Hash：对象属性、任务简要状态。
- List：简单队列或消息列表。
- Set：去重、标签集合、权限集合。
- Sorted Set：排行榜、延迟任务、按分数排序。
- Stream：带消费组的消息流，适合可靠消费场景。

### 38. Redis 为什么快？

- 数据主要在内存中，避免了大量磁盘随机访问。
- 使用高效的数据结构和事件循环处理网络请求。
- 协议简单，命令执行路径短。
- 但单条命令仍可能阻塞 Redis，不能执行超大集合遍历或复杂 Lua 脚本。

### 39. 什么是缓存穿透、击穿和雪崩？

- 穿透：查询不存在的数据，缓存和数据库都被打到。可用缓存空值、布隆过滤器和参数校验。
- 击穿：某个热点 Key 过期瞬间大量请求访问数据库。可用互斥锁、逻辑过期和热点预热。
- 雪崩：大量 Key 同时过期或 Redis 故障。可用随机过期时间、分批发布、降级和多级缓存。

### 40. Redis 分布式锁如何设计？

- 使用 `SET lock_key token NX EX seconds` 原子加锁。
- 释放锁时必须校验 token，只能删除自己持有的锁，通常使用 Lua 保证判断和删除原子化。
- 设置合理过期时间，必要时通过看门狗续期。
- 业务执行时间不可控时，单纯 Redis 锁不等于强一致事务；关键写入还需要数据库版本号或幂等约束。

### 41. Redis 如何实现延迟任务或 Agent 队列？

- 简单场景使用 Sorted Set，以执行时间作为 score。
- Worker 周期性拉取到期任务，并通过状态更新或锁避免重复领取。
- 可靠消息场景使用 Stream + Consumer Group，处理确认、重试和死信。
- 任务本体和最终状态仍应持久化到数据库，Redis 只作为调度或加速层。

### 42. Redis 持久化方式有哪些？

- RDB：定时生成快照，恢复快，但可能丢失最近一段时间的数据。
- AOF：记录写命令，数据更完整，但文件可能更大，需要重写。
- 实际选择取决于数据是否可重建、允许丢失的数据量和恢复时间要求。
- 任务状态、审批记录等关键数据不能只放在 Redis 中。

### 43. Redis 内存淘汰策略如何选择？

- 缓存场景可使用 `allkeys-lru` 或 `allkeys-lfu`。
- 只允许淘汰设置过期时间的 Key 时使用 `volatile-lru` 或相关策略。
- 关键任务状态不应和普通缓存混用同一个淘汰空间。
- 需要监控内存使用、命中率、淘汰次数和大 Key。

## 七、Agent 与 Java 后端结合的场景题

### 44. 如果用 Spring Boot 重写 Agent 后端，你会如何拆分模块？

可以按领域边界拆分：

- `agent-core`：Agent Loop、消息模型、终止条件和错误模型。
- `provider`：模型 Provider 接口及 OpenAI 兼容实现。
- `tool`：工具注册、Schema、权限和执行器。
- `task`：任务状态机、队列、取消、恢复和重试。
- `memory`：长期记忆、上下文压缩和会话检索。
- `knowledge`：文档解析、切分、检索、重排和引用。
- `infrastructure`：MyBatis Mapper、Redis、消息队列和外部 API 适配器。

核心领域层依赖接口，具体数据库、缓存和模型实现放在基础设施层，便于替换 Provider 和存储方案。

### 45. 如何保证多个 Worker 不会重复执行同一个 Agent 任务？

- 数据库领取任务时使用条件更新：只有 `status = queued` 的任务才能改为 `running`。
- 使用版本号、租约时间或分布式锁处理并发竞争。
- 每个工具步骤使用幂等 Token，重复领取也不会造成重复副作用。
- Worker 崩溃后由超时扫描任务重新入队，但要先确认租约已过期。

### 46. 审批等待期间，任务上下文应该放在哪里？

- 任务状态、审批请求、当前步骤和上下文快照持久化到数据库。
- 大型工具结果存对象存储或文件系统，数据库保存引用和摘要。
- Redis 可保存短期唤醒信息，但不能作为唯一事实来源。
- 审批回调必须校验任务 ID、步骤 ID、审批版本和授权人，防止旧审批误恢复任务。

### 47. 如何设计 Agent 的可观测性？

- 每个请求生成 `trace_id`，每个任务、步骤和工具调用生成对应的 Span 或事件 ID。
- 记录模型耗时、Token、工具耗时、重试次数、审批等待时间和失败原因。
- 日志、指标和事件中统一携带 session、task、step 标识。
- 对提示词和工具参数做脱敏，避免把密钥或个人隐私写入日志。

### 48. 如何测试 Agent 系统？

- 单元测试：状态机迁移、参数校验、风险评分、幂等逻辑和上下文压缩。
- 集成测试：MySQL、Redis、模型 Provider 和工具适配器。
- 契约测试：模型输出、工具 Schema 和前后端事件协议。
- 故障测试：模型超时、工具重复回调、Worker 崩溃、审批过期和网络断开。
- 评测测试：RAG 召回率、引用准确率、拒答率和端到端任务成功率。

## 八、结合项目经历的回答模板

### 49. 你遇到过最难的问题是什么？

可以按以下结构回答：

> 在复杂任务中，工具调用可能因为网络重试或客户端重复请求而执行多次。我的处理方式是为每个步骤生成幂等 Token，执行前检查幂等记录，成功后原子保存结果；对于无法直接回滚的外部操作，再通过 Saga 补偿或人工审批处理。这样既保证任务可以恢复，也避免重复执行污染数据。

### 50. 你的项目和普通工作流引擎有什么区别？

- 普通工作流通常由预先配置的节点和边决定流程。
- Agent 的下一步由模型根据上下文和工具结果动态规划。
- 因此 Agent 需要额外处理模型不确定性、工具参数校验、风险审批和上下文管理。
- 比较成熟的方案是：模型负责提出计划，服务端负责验证、授权、执行和记录。

### 51. 如果让你继续优化项目，你会做什么？

建议选择真实且可落地的方向回答：

- 增加任务事件的数据库事务和版本控制，提升多 Worker 并发下的一致性。
- 引入更完整的评测集，量化工具选择、RAG 召回和最终任务成功率。
- 增加模型、工具和任务级成本统计，支持预算和限流。
- 将高风险工具接入更细粒度的资源权限与审批策略。

## 十、回答原则

1. 先讲结论，再讲原理，最后结合项目。
2. 区分“已经实现”“理解原理”和“计划采用”，不要把学习内容说成项目成果。
3. 遇到架构题先明确一致性、可靠性、延迟和成本之间的取舍。
4. 不只说使用了某个组件，要说明它解决了什么问题，以及失败时怎么办。
